# Behavioral source workflow

The source workflow selects `behavioral-0.5.8/v1` explicitly and
composes the [authored frontend](behavioral-frontend.md),
[full encoder](behavioral-encoding.md#full-profile-runtime) and checked temporal
serializer. The [behavioral matrix](behavioral.md#complete-feature-and-evidence-matrix)
retains the full qualification obligations. Source-workflow acceptance is recorded
in the
[integration review](https://github.com/kbak/clafer-compiler-lean/issues/79);
[main integration](qualification.md#main-integration) requalifies the final pin.

## Reuse and boundaries

`Frontend.Behavioral.parseAndElaborate`, `Elaborated.check` and `Elaborated.run`
already provide model, assertion and scenario requests with source ownership.
`Backend.Alloy.Behavioral.Full.compile` supplies checked full-profile lowering;
its existing frontend soundness and bounded-completeness theorems cover the
in-memory composition. `Temporal.Text.render` checks reconstruction and retains
generated byte mappings. The native driver reuses these APIs and the existing
strict JSON decoder, UTF-8 diagnostics and atomic output replacement.

The first-slice JSON driver cannot admit full expressions or inherited references.
Its trace decoder also has no scalar fields. Reuse its closed-schema and global
identity checks while keeping the full profile's scalar observations explicit.
Full decoding preserves all scalar rows at every frame, including absent identities;
[source reference observations](behavioral-encoding.md#absent-reference-observations)
restrict those values to live heads. Potentially zero divisors remain an admission
error even when a particular observation would disappear or cancel.
The exact-candidate phase clock, global isomorphism and retained replay machinery
in `scripts/comparison/temporal_compare.py` can preserve lasso presentations.
Its historical Haskell adapter only admits a guarded structural subset; it cannot
certify full source pairing by relabelling that subset's receipts.

Pinned upstream S7 supplies strict partial finite checking and exact context
bundles. Its finite carrier does not contain all mathematical integers; a full
primitive adapter requires its own observation correspondence. Existing full
encoder completion/observation proofs retain that boundary. Haskell source and
the accepted PR113 adapters supply revision-specific comparison evidence, never
the independent source meaning.

Lean/Std parser, JSON, list/vector and IO facilities, Python's standard library,
the existing Alloy 6.2.0 bridge and GNU time meet the infrastructure needs.
Adding another CLI, parser, solver or benchmark package would duplicate these
facilities without supplying Clafer-specific source/target correspondence.
No new dependency or vendored Lean semantic definition is selected. The finite
Python test adapter below directly evaluates the registered observation equations;
it is not an imported or certified upstream checker. Original code is
MIT; imported Lean libraries retain Apache-2.0 and external tools retain the
licenses in the [source register](sources.md).

Initializer and absence qualification reuses `behavioral_initializer_cases`,
`absence_cases`, the full source observer, `behavioral_haskell`, PR113 capture and
the existing exact-lasso pinning/graph comparison. The ordinary Haskell pairing
fixes absent scalar reference rows to empty; it cannot detect extra reference
tuples that its generated facts permit outside live heads. A separate raw-table
probe therefore retains such rows and compares the complete trace, with a
live-only projection used solely to demonstrate why display can hide a difference.
The pinned Choco CLI already reads explicit source with hard constraints and
integer references. It supplies static satisfiability controls where supported;
the guarded structural `ChocoInstances` adapter deliberately rejects those forms
and is not broadened. No new parser, graph-isomorphism library, solver bridge or
dependency is needed. These are executable comparison boundaries, not new proofs
or a Lean Choco backend.

## Native commands and bounds

`compile-behavioral-source` selects this profile; static `compile-source` and
resolved `compile-behavioral-ir` retain their existing protocols. For example:

```sh
clafer-compiler compile-behavioral-source model.cfr --bounds bounds.json --output model.als
clafer-compiler compile-behavioral-source model.cfr --bounds bounds.json --output check.als --assertion 0
clafer-compiler compile-behavioral-source model.cfr --bounds bounds.json --output run.als --scenario scenario.cfr --owner 1
```

The default command searches for a model. `--assertion N` selects a zero-based
assertion and emits a counterexample search: an undefined or false property at
any applicable live context violates the universal assertion. `--scenario FILE`
adds constraints to the model; `--owner ID` selects their declaration context,
with root as the default. Assertions are never silently added as model facts.
A scenario file accepts constraints, not declarations or additional assertions.
The two property options are mutually exclusive. At most one input, bounds or
scenario stream may be `-`. Output `-` writes stdout; file output uses the shared
atomic replacement route. `--format json` includes the actual Alloy text,
resolved expression inspection, declaration/field maps and source byte spans.

For the source `A ?`, a complete bounds document is:

```json
{
  "version": "clafer-behavioral-bounds/2",
  "profile": "behavioral-0.5.8/v1",
  "objects": 2,
  "bitwidth": 3,
  "minSteps": 1,
  "maxSteps": 3,
  "declarations": [
    {"id": 0, "size": 1, "exact": true},
    {"id": 1, "size": 1, "exact": false}
  ],
  "integers": {"lower": 0, "upper": 1}
}
```

IDs follow resolved declaration order, including generated enum declarations;
root is retained explicitly. Every nonprimitive declaration needs exactly one
scope. Scopes count the **whole inherited view**, across the whole trace; a
supertype's budget includes its subtype instances. `objects` bounds the disjoint
ordinary inventory, including root and unused slots. The implicit `int` declaration
has no object scope. `integers` bounds the scalar observations; `bitwidth` separately
bounds literals, generated counts and every intermediate operation. The compiler
rejects unsafe conservative range estimates. An exact declaration scope is an
emitted view-cardinality constraint, not necessarily an exact direct Alloy signature.

`minSteps` and `maxSteps` count stored positions and their outgoing edges, including
the looping edge. They do not select the loop index. Exact comparison adds a
separate phase clock to fix that index. Bounds JSON is closed: duplicates, unknown
fields, noncanonical integer tokens, missing scopes and wrong versions/profiles
are errors. Source failures retain UTF-8 byte offsets and line/column diagnostics;
range failures identify the offending authored body when available.

## Successful warning protocol

`Driver.BehavioralSource.compileReport` adds a `Report` with the existing `Product`
and a list of `Frontend.Behavioral.Warning`. It collects authored-model warnings
after full compilation, followed by warnings from the selected scenario. Each
document is ordered by source start byte, with enclosing expressions first on
ties. Assertions are part of the authored inventory even when not selected.
Scenario source is parsed again for reporting after its request has succeeded;
the established request/product APIs and closed compilation schema stay unchanged.

The CLI writes successful warnings to stderr and returns exit `0`. Alloy or JSON
stdout and output files contain only the existing compilation product. Under
`--diagnostics json`, stderr is newline-delimited JSON with one `clafer-warning/1`
record per warning: `version`, `severity` (`warning`), `code`, `phase`
(`elaboration`), `message`, `operator` and `primary`. The primary location has
`kind` (`source`), logical `file`, zero-based half-open UTF-8 `startByte`/`endByte`
and one-based `line`/scalar `column`. Text mode prints the location, warning code
and message. Codes, severity, operators and locations are stable; English wording
is not. The [frontend contract](behavioral-frontend.md#literal-empty-navigation-and-successful-warnings)
defines the two warning codes and exact detection policy.

Warnings appear only after successful compilation and output writing. Failures
retain the existing single error protocol and exit category, without partial
warning output. `--version` identifies the source policy and warning schema.
Static source and resolved-IR commands retain their existing behavior.

## Composition and assurance

`Driver.BehavioralSource.compile` calls the actual parser/elaborator, property
request selector, full compiler and checked temporal renderer. Its `Product`
retains the successful `Full.compile` equation. `BehavioralSyntax` exports the
resolved seven-family expression tree and computes a traversal depth; this is
inspection output, not a second admitted source language. Modifier expansions
participate in the same depth calculation. Exhausted source traversal allocation
is explicitly unsupported.

The [existing full theorems](behavioral-encoding.md#full-profile-proof-components)
remain the composed in-memory assurance: successful elaboration and compilation,
`SourceElaborated`, related traces, finite observations, primitive-shape premises,
identity/step scopes and `Fits` arithmetic conditions are explicit. The driver
adds no unchecked axiom and makes no theorem about filesystem IO, parser grammar,
JSON, native code, the Analyzer parser or SAT4J. Source spans, deterministic text,
closed protocols and runtime isolation are executable test obligations.

`Driver.BehavioralSourceTrace.decode` reuses the actual Analyzer table parser and
`Full.decode`. Scalar tuples contain a known ordinary head and a canonical signed
integer string. Every identity has one scalar slot per frame, including unused
slots; these are distinct from primitive mathematical integer objects. Duplicate
or missing scalar heads, unknown fields, altered metadata, changed static parents
and malformed lasso shapes are rejected. `clafer-behavioral-trace/2` carries fixed
direct types, parents, live rows, declared reference rows and scalar values.

## Exact comparison and replay

The [full source harness](../scripts/comparison/behavioral_source.py) compiles the
retained authored input with the production executable. It exports the actual
resolved expressions, fixes every target table under one global alias map and
uses the existing phase clock to force the complete lasso presentation. A SAT
witness is decoded by the native full decoder and compared with one graph
isomorphism across all frames, including scalar values. Per-frame renaming is
never permitted. Negative candidates are independently fixed in the same way.

The source target's signatures are static. After checking the candidate against
the caller's bounds, the harness supplies their observed populations as exact
Alloy scopes. Those cardinalities already follow from the fixed signature-table
equations, including empty signatures; they add no restriction to that exact
candidate query. The original compiler output and caller bounds remain in the
bundle. This reuses the existing Analyzer scope API and request receipts so the
translator can simplify bounds before expanding quantified formulas, without
rewriting emitted formulas, changing solver options or increasing resource limits.
Regressions cover both satisfied and violated candidates below loose upper bounds.

The supplementary [finite source observer](../scripts/comparison/behavioral_observation.py)
evaluates structural obligations, effective modifiers, strict partial expressions,
both source signs, frozen environments and the time-zero/loop history directly.
It does not read generated target formulas or invoke the encoder to decide truth.
This is **tested reference code**, not a certified instance of S7's generic
finite adapter. The first-slice upstream checker remains separately kernel proved;
the full compiler theorems separately establish source/target correspondence.
The finite observer must not be reported as an extension of that verified checker.
Its equations are checked against the immutable upstream source register and
positive/negative observations, and remain an independent-review boundary.

```sh
python3 scripts/comparison/behavioral_source.py run case.json /tmp/source-case-UNIQUE --tools "$CLAFER_ORACLE_TOOLS"
python3 scripts/comparison/behavioral_source.py replay /tmp/source-case-UNIQUE/case /tmp/source-replay-UNIQUE --tools "$CLAFER_ORACLE_TOOLS"
```

Each bundle retains input, bounds, resolved output, candidate, native decode,
exact target query, solver request/options/result, source/tool/binary identities,
measurements and an artifact inventory. Replay rejects changed source, tools,
binaries, candidates or receipt bytes. `source-only` and `target-only` differences
remain explicit; failures and timeouts cannot pass. The first-slice discrepancy
minimizer remains limited to its documented profile and row reductions.

The runtime bundle records the host, CPU, memory, Lean and tool versions through
the existing qualification recorder. GNU time records production compilation wall
time and maximum RSS. Python records
finite observation and overall comparison durations. Each measurement retains
identity counts, scopes, bitwidth, finite value interval, frame count and loop.
These are descriptive measurements, not a performance guarantee. Frozen capture
uses the encoder's finite alias enumeration, which includes signed integer
candidates: its cost is exponential in identity capacity plus integer-domain
size. Use the smallest sufficient width; a narrow scalar interval does not shrink
that signed capture domain. This cost is inherited from the accepted full encoder. Nested captures and
aggregates can exhaust the native stack even with small object scopes;
[bounded lowering work](https://github.com/kbak/clafer-compiler-lean/issues/132)
tracks that operational limitation. Resource failures are not semantic results.

## Initializer and absence qualification

The [initializer cases](../tests/behavioral_initializer_cases.py) and
[absence cases](../tests/behavioral_source_cases.py) are shared by the native
compiler/Alloy checks and pinned Haskell comparisons in
[`test_initializer_absence_reference_matrix`](../tests/test_behavioral_source_comparison.py).
Expected source outcomes come from the accepted initializer and absence contracts.
Every completed comparison checks supplied identities, actual parents, live sets,
reference tuples, integer observations, stored frames and the loop edge. A negative
exact query rules out that candidate at its recorded bounds; it is not unrestricted
model UNSAT.

The matrix distinguishes every-live `=` from instance-birth, parent-birth and
global-time-zero `:=`. It includes late heads, rebirth and loop-edge births,
fresh children after parent replacement, original RHS names and temporal context,
inherited clocks and conjunctive equations, changing RHSs under `finalref`, empty
heads with undefined RHSs, repeated bag targets and missing/extra target images.
Static controls check both operators against hard conflicts; assertions remain
separate from model constraints. Abstract scalar admission is checked before
solving, including unused abstracts and static inputs. Conservative range rejection
and unsupported admission are not satisfiability verdicts.

The following reference limitations are retained against
`fca0deb9c766261f5c0d2ae57af4ba9b07e1279a`. They do not change accepted source meaning.
The qualification disposition requires independent review in
[the owning task](https://github.com/kbak/clafer-compiler-lean/issues/127).

| Boundary | Distinguishing observation and consequence |
| --- | --- |
| Absent references | The reference permits raw object and integer tuples at absent or never-live heads. A live-only display can be identical while complete reference tables differ. Raw-reference probes retain those tuples and a global-renaming control distinguishes this from symmetry. |
| Original temporal RHS environment | `Box.x := if X (some flag) then 1 else 0` with Box disappearing has RHS value zero under the original root lifetime. The reference rejects that observation and accepts value one, exposing cancellation after moving the RHS into the child. Both discrepancy directions are replayed. |
| Temporal selection under `finalref` | A model whose only temporal syntax is `finalref` treats `:=` differently in the two compilers. An explicit `always` control separates selection from birth/finality behavior. No unconditional `:=`/`=` equivalence follows from finality. |
| Captures and definedness | The registered temporal-`let` exclusions also affect initializer conditions. A captured absent head's strict extraction is undefined even where the reference accepts it; empty initializer heads suppress the complete RHS. |
| Parented abstract omission | The reference and compiler retain different effective local multiplicities for an omitted parented abstract. The strict declaration-pairing gate records `unpaired`, with both analyzed declarations retained; no relaxed bijection or agreement verdict is substituted. |
| Abstract scalar admission | The reference admits an unused abstract with a multi-target `:=` RHS. The compiler diagnoses unsupported scalar admission in both static and temporal source; a repeated identical literal is the admitted control. |

Raw scalar probes retain two distinct judgments: `source` is the finite source
observer's verdict for the live projection, while `reference_domain: violated`
records extra absent-head tuples forbidden by source structural validity. A SAT
raw probe is a `target-only` discrepancy even if that projection is satisfied.
Compiler scalar storage remains total and unobservable at absent heads; it is
not itself an invalid reference tuple. Replay binds the probe settings and checks
the full raw tables, including the solver's exact frame count and loop.

Static Choco controls use the existing pinned explicit-source CLI and generated
scope sidecar, preserving hard constraints and assertions from the same Haskell
capture. They establish bounded static outcomes only. Temporal Choco solving is
unsupported and no Lean Choco backend is added. Historical oracle profiles and
their original receipts remain unchanged. Current bundles retain source hashes,
decoded JSON and original bytes, tool identities, bounds, actual commands,
raw witnesses and discrepancy directions outside the repository.
